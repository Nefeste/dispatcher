# Содержание: медицина, звонящие, карта

Откуда берутся факты игры, что запрещено и как проверяется. Общие правила — в уставе
([`06-content.md`](https://github.com/Nefeste/gornitsa/blob/main/docs/06-content.md),
[«Контент» в `05-rules.md`](https://github.com/Nefeste/gornitsa/blob/main/docs/05-rules.md#контент)); здесь — как они
выполнены в «Диспетчере 03». Формат записей — [`04-data-model.md`](04-data-model.md).

## 1. Медицина

Правила медицинского содержания «Анамнеза» действуют здесь целиком (его `AGENTS.md`, «Medical content rules», и
`docs/11-content.md`):

- каждая запись — **из названного первоисточника**, с источником в `sources`; никогда по памяти;
- порядок Минздрава и клиническая рекомендация — по их записи: номер приказа и дата или ID рубрикатора
  `cr.minzdrav.gov.ru`, точное название, год, адрес карточки;
- частоты — полосами (`always` … `never`), точное число — только со своим источником;
- **ни доз, ни схем лечения, ни торговых названий** — классы препаратов и МНН, и только в тексте разбора, если без этого
  не объяснить исход;
- тексты — своими словами, без пересказа абзацев рекомендаций, учебников и энциклопедий;
- **никаких данных, списков и устройства из других игр** — ни про диспетчеров (911 Operator, 911 Emergency Dispatcher и
  любые другие), ни про больницы; ни «для начала», ни «чтобы сравнить»;
- каждая новая запись — `review: draft`; `checked` ставит только человек.

**Копии «Анамнеза».** Болезни, признаки и факторы риска игры берутся из «Анамнеза» байт в байт
(ADR [0002](adr/0002-med-model-from-anamnez.md)). Их источники уже в записях. Своё у «Диспетчера» — записи «по
телефону», и у каждой свои источники:

| Поле записи «по телефону» | Откуда факт |
|---|---|
| форма вызова (экстренная или неотложная) и повод | порядок оказания скорой медицинской помощи — перечни поводов ([§4](#4-источники)) |
| вид бригады | тот же порядок — виды и состав выездных бригад |
| профиль больницы | порядок оказания помощи по профилю (при ОНМК, ОКС, травме) или клиническая рекомендация |
| окно — после какого срока опоздание меняет исход | клиническая рекомендация по состоянию, с ID |
| признак угрозы жизни (`threat`) | перечень поводов для экстренной формы в порядке скорой помощи |
| кто из звонящих может сказать о признаке (`tell`) | решение агента по смыслу признака: что видно и что знают близкие ([§2](#2-звонящие)) |
| время на месте, доля госпитализаций | число баланса, «оценка» — в записи так и помечено |

**Граница: игра, а не обучение** (ADR [0007](adr/0007-game-not-training.md)). Нет записей «что посоветовать
звонящему». Если источник описывает советы по телефону, в игру они не берутся.

## 2. Звонящие и разговор

- **Звонящие придуманы.** Ни записей настоящих звонков, ни их пересказов, ни историй из новостей — это чужие
  персональные данные. Слова звонящих пишет агент по голосу студии
  ([`09-voice.md` устава](https://github.com/Nefeste/gornitsa/blob/main/docs/09-voice.md)), без грубости и без насмешки над
  испуганным человеком.
- **Что знает звонящий** — по смыслу признака, а не по источнику. Видимое (лежит, не отвечает, кровь, судороги) видят
  все. Жалобы (болит, давит) знает сам больной и тот, кому он сказал. Болезни и лекарства знают близкие. Каждая
  полоса `tell` — решение агента, записанное в записи «по телефону». Проверка — «виртуальный диспетчер» и игра
  владельца.
- **Вопросы диспетчера** — свои слова. Что диспетчер выясняет при приёме вызова (адрес, кто болен, возраст, что
  случилось), — по официальным памяткам «что сказать диспетчеру» ([§4](#4-источники)). Порядок и формулировки чужих
  протоколов опроса не копируются.

## 3. Карта

- **Улицы — OpenStreetMap**, лицензия Open Database License 1.0 (ADR [0004](adr/0004-osm-map.md)). Выгрузка — с адреса
  и датой в паспорте карты; строка «© участники OpenStreetMap» — на карте и в «Об игре».
- **Подстанции и больницы вымышлены**: свои имена («Подстанция № 1», «Городская больница № 2») и места, выбранные
  дизайнером. Имени настоящей станции скорой, подстанции или больницы в игре нет. Номера в именах выбираются так, чтобы
  не совпадать с настоящими учреждениями района смены; это проверяется по OSM (теги `amenity=hospital`,
  `emergency=ambulance_station`) при сборке карты.
- **Скорости на дорогах** — числа баланса, «оценка» ([`08-game-design.md`](08-game-design.md), §9).

## 4. Источники

Сверены с первоисточником; дата сверки — в строке. Источник, который не удалось открыть, так и помечен и в записи не
идёт, пока его не сверят.

Ключ из первого столбца пишется в `sources` записи вместе с пунктом.

### Медицина состояний

Источники болезней и признаков — в самих записях «Анамнеза» (`content/med/`). Своё у записей «по телефону» — профиль
больницы и окно состояния — пишется при наполнении содержания прототипа (часть П4) и сверяется с рубрикатором
клинических рекомендаций, как в «Анамнезе» (`bun tools/content/clinrecs.ts`).

## 5. Проверки

Валидатор «Анамнеза» (`tools/content/load.ts`) и свои правила:

- у каждого признака и состояния, которые есть в игре, есть запись «по телефону», и наоборот;
- копии в `content/med/` сходятся с `content/med/FROM.yaml` (коммит «Анамнеза», SHA-256);
- у каждой записи «по телефону» есть `sources` с ключом из §4 и `review`;
- `threat: true` — только у признаков, которые есть в перечне поводов для экстренной формы (ссылка на пункт);
- окно — с источником, кроме «оценки», помеченной так явно;
- у каждого состояния есть хотя бы один вопрос, который меняет решение о форме;
- ни доз, ни торговых названий в текстах (проверка «Анамнеза» `tools/content/brands.ts`);
- кириллица вне `src/i18n/` и `content/` — ошибка (тест i18n);
- имена подстанций и больниц не совпадают с именами учреждений района в выгрузке OSM.

После партии записей — сборка, валидатор и «виртуальный диспетчер»; отчёт — в описании коммита.
